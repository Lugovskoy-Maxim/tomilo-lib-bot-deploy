## Личный профиль в Telegram

Основной запуск `node index.js` теперь также принимает сообщения в личном чате. Доступны только привязка (`/link КОД`, `/start link_КОД`), информация о профиле (`/profile`) и настройки (`/notifications`). Код создаётся на сайте: Профиль → Настройки → Telegram. Поиск, каталог, PDF и чтение в боте не добавляются.

Уведомления о главах в закладках и звук переключаются отдельно кнопками профиля и сохраняются в серверном API. Для личных уведомлений используется настройка звука пользователя; клиент Telegram также может отключать звук самостоятельно. Персональная очередь работает независимо от пауз канальных публикаций.

Требуются текущие изменения Telegram API в `tomilo-lib-server` и одинаковый `BOT_API_SECRET` / `TELEGRAM_BOT_API_SECRET` у бота и сервера. `NOTIFY_PERSONAL_BOOKMARKS=false` отключает обработку личной очереди. Существующие канальные публикации и MAX продолжают работать.

У этого токена должен быть один процесс, принимающий обновления Telegram, и один обработчик персональной очереди. Перед запуском остановите отдельный `tomilo-lib-telegram-bot`, если он использует тот же токен. При запуске используется polling; библиотека Telegram переключает существующий webhook на polling.

Проверки: `npm test`.

# Tomilo Lib Bot

Telegram-бот для уведомлений о новых главах, тайтлах и личных закладках.

Жалобы отправляет именно этот контейнер, поэтому при `WG_ENABLED=true` запросы
к Telegram проходят через его WireGuard. API только хранит очередь. Для доставки
задайте в `.env` бота `TELEGRAM_CHAT_ID2`, `TELEGRAM_REPORTS_THREAD_ID=3` и
`BOT_API_SECRET`; на API должен быть такой же `TELEGRAM_BOT_API_SECRET`.

## Обновить из Git и перезапустить контейнер

Из каталога репозитория на сервере:

```sh
bash update-container.sh
```

Скрипт получает текущую ветку из `origin`, выполняет только fast-forward,
собирает образ и пересоздаёт **только `bot`**, не останавливая остальные сервисы
и не удаляя том с состоянием. Повторный запуск пересобирает и перезапускает
контейнер даже без новых коммитов. Локальные изменения, неотслеживаемые файлы
или расхождение истории останавливают обновление. `.env` не исполняется как shell-код.
Нужны доступ к Git, Docker и современный Docker Compose с `--wait-timeout`.
Если первоначальный запуск использовал `-p`, передайте то же имя через `--project`.

Для другого сервиса/репозитория:

```sh
bash update-container.sh --repo /absolute/path/to/repository --compose compose.yaml --service bot --branch main
```

Для VPS API, который использует уже опубликованный образ:

```sh
bash update-container.sh --repo /absolute/path/to/tomilo-lib-server \
  --compose docker-compose.vps.yml --service api --branch regru \
  --mode pull --env-file /absolute/path/to/deploy.env --project YOUR_EXISTING_PROJECT
```

Укажите реальные пути и существующее имя Compose-проекта. `deploy.env` должен
содержать переменные используемого Compose (`API_IMAGE`, `WEB_IMAGE`, `MODERATION_IMAGE`,
`APP_ENV_FILE` и прочие). В режиме `pull` код из Git **не собирается**: CI должен заранее
опубликовать образ, а `API_IMAGE` — указывать на нужную версию. Это не замена текущему
release-деплою, если он использует каталоги релизов или blue/green.

При ошибке сборки старый контейнер продолжает работать. При ошибке запуска скрипт
возвращает ненулевой код; автоматического отката контейнера нет. Сервисы без healthcheck
проверяются только на состояние `running`. Деплой GitHub Actions и этот скрипт не следует
запускать одновременно. Скрипт не устанавливает расписание и не запускается сам по себе.

## Отдельный бот для MAX — без VPN

Готов самостоятельный режим MAX: публичные уведомления о новых главах,
новых тайтлах, рейтинге и просмотрах, ежедневные промо, подсказка о скрытых
главах, поддержка проекта и недельные лидеры месяца. Он работает напрямую с
официальным `https://platform-api2.max.ru` и не использует WireGuard.

Создайте и верифицируйте чат-бота в кабинете MAX для партнёров, добавьте его
администратором в нужный канал и получите `MAX_BOT_TOKEN` и `MAX_CHAT_ID`.
MAX требует верифицированный профиль организации, ИП или самозанятого и
модерацию бота. Затем:

```sh
cp .env.example .env.max
# В .env.max: TELEGRAM_ENABLED=false, MAX_ENABLED=true,
# MAX_BOT_TOKEN=..., MAX_CHAT_ID=..., API_URL=..., SITE_URL=...
mkdir -p certs
# Положите корневой и выпускающий сертификаты Минцифры в certs/mincifry.pem
docker compose -f compose.max.yaml up -d --build
```

`compose.max.yaml` не монтирует `/dev/net/tun`, не выдаёт `NET_ADMIN` и не
запускает WireGuard. Сертификат Минцифры нужен для TLS-доверия к API MAX, это
не VPN. Личные уведомления о закладках пока остаются Telegram-сценарием:
для MAX потребуется отдельная привязка аккаунта сайта к `user_id` MAX на
сервере.

Личные уведомления о закладках требуют, чтобы API сервера поддерживал очередь
`/telegram/bot/pending-chapter-notifications`. Если этого маршрута ещё нет,
бот выводит одно предупреждение и прекращает его опрашивать до перезапуска;
публичные уведомления продолжают работать.

По умолчанию бот использует тихие часы с 00:00 до 08:00 по Москве. В это время
уведомления отправляются сразу, но Telegram доставляет их без звука; обновления
не накапливаются к утру. Настройки находятся в `.env`: `QUIET_HOURS_START`,
`QUIET_HOURS_END`, `MESSAGE_COOLDOWN_MS`, `MAX_PUBLIC_NOTIFICATIONS_PER_RUN`
и `MAX_PERSONAL_NOTIFICATIONS_PER_RUN`.

Также бот один раз в московские сутки размещает пост о приложении для Android
(RuStore и GitHub Releases). Пост о поддержке проекта публикуется не чаще
одного раза в четыре часа. Параметры `NOTIFY_DAILY_APP_PROMO` и
`NOTIFY_DAILY_SUPPORT` включают их, а `SUPPORT_PROMO_INTERVAL_MINUTES`
задаёт интервал поддержки (минимум 240 минут),
а `DONATE_URL` и `DONATE_URL_TBANK` задают способы поддержки. Публикация
подчиняется тихим часам и общей очереди сообщений.

Раз в неделю бот также может публиковать иллюстрированную подсказку о включении
скрытых глав через меню под аватаром. Управление: `NOTIFY_HIDDEN_CHAPTERS_GUIDE`
и `HIDDEN_CHAPTERS_GUIDE_INTERVAL_HOURS` (минимум 24 часа).
После этих ежедневных постов бот делает паузу для всех новых уведомлений;
по умолчанию 20 минут, настраивается через `DAILY_PROMOTION_PAUSE_MINUTES`.

После каждого нового поста бот ставит случайную обычную реакцию (`✨`, `🔥`,
`❤️`, `👏`, `😍` или `🎉`). По умолчанию 15% постов остаются без реакции;
это настраивается через `POST_REACTION_SKIP_PERCENT` или отключается
`POST_REACTIONS_ENABLED=false`.

## Запуск в Docker

Скопируйте пример окружения и заполните Telegram-токен и адрес API:

```sh
cp .env.example .env
docker compose up -d --build
```

Состояние бота хранится в именованном томе `bot-state`, поэтому перезапуск и
пересборка контейнера не создают повторные уведомления. Контейнер ограничен
192 МБ памяти, 0.5 CPU и 80 процессами; при необходимости лимиты находятся в
`compose.yaml`.

### WireGuard внутри контейнера

1. Создайте конфигурацию VPN, не добавляя её в Git:

   ```sh
   mkdir -p wireguard
   cp wireguard/wg0.conf.example wireguard/wg0.conf
   chmod 600 wireguard/wg0.conf
   ```

2. Заполните `wireguard/wg0.conf` данными провайдера и в `.env` задайте
   `WG_ENABLED=true`.

3. Перезапустите сервис:

   ```sh
   docker compose up -d --build
   ```

WireGuard запускается в сетевом пространстве контейнера. Его маршруты, DNS и
`AllowedIPs` не меняют общий интернет хоста. При `AllowedIPs = 0.0.0.0/0, ::/0`
только трафик бота уходит через VPN; чтобы VPN не использовать, оставьте
`WG_ENABLED=false`.

Некоторые VPS запрещают контейнерам менять `net.ipv4.conf.all.src_valid_mark`.
Образ обрабатывает это ограничение без изменения host-системы: WireGuard,
маршруты и правила firewall по-прежнему создаются только в контейнере.

Если VPN-провайдер не пропускает API сайта, добавьте его домен в
`WG_BYPASS_HOSTS` (по умолчанию `tomilo-lib.ru cdn.tomilo-lib.ru`). При запуске контейнер
разрешает IP домена и создаёт маршрут-исключение только в своём namespace:
Telegram и S3-обложки остаются внутри VPN, а API сайта доступен напрямую.

Проверить запуск можно так:

```sh
docker compose logs -f bot
```

Не публикуйте `wireguard/wg0.conf`: в нём находится приватный ключ.

## Дублирование в MAX

Создайте чат-бота MAX, добавьте его в целевой канал администратором и укажите
в `.env` `MAX_ENABLED=true`, `MAX_BOT_TOKEN` и `MAX_CHAT_ID`. Бот отправляет
в MAX те же публичные уведомления о главах, рейтинге и просмотрах с HTML и
кнопкой на сайт; анонс тайтла, обновляемый в Telegram в течение дня, также
редактируется в MAX. Без этих переменных интеграция отключена и на Telegram
не влияет.

API MAX использует сертификаты Минцифры. Скачайте корневой и выпускающий
сертификаты из официальной инструкции MAX, сохраните их в одном PEM-файле
`certs/mincifry.pem` и добавьте в `.env`:

```env
NODE_EXTRA_CA_CERTS=/certs/mincifry.pem
```

Папка `certs` монтируется контейнеру только на чтение и не попадает в образ.
Без этих сертификатов Node.js обычно не сможет установить доверенное TLS-
соединение с `platform-api2.max.ru`.
